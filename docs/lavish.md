# Работа с Lavish

Lavish открывает созданные агентом HTML-материалы в браузере и позволяет обсуждать правки прямо на странице: выделять текст, отмечать элементы и отправлять замечания агенту. В этом проекте все новые дашборды создаём и дорабатываем через Lavish.

## Установка и запуск

В проекте уже установлен `lavish-axi` версии `0.1.87`. Требуется Node.js 22 или новее. Все команды ниже выполняются из корня проекта:

```bash
cd /home/dima/ai_tutoring
```

После переноса проекта на другой компьютер или удаления `node_modules` восстанови зависимости:

```bash
npm ci
```

Навык для агента: [SKILL.md](../.agents/skills/lavish/SKILL.md). Глобальная установка не требуется.

## Как заказать дашборд

В чате опиши тему, уровень учеников, учебную цель и нужные взаимодействия. Например:

> Создай через Lavish дашборд по линейной функции для 7 класса. Пусть ученик меняет коэффициенты k и b и видит, как меняются график и формула. Сохрани его в dashboards/linear-function/.

Агент создаёт HTML и необходимые ресурсы, проверяет материал и открывает его через Lavish. Сам Lavish служит средой просмотра и обратной связи; содержание, графики и интерактивность реализуются в HTML, CSS и JavaScript.

## Где хранить файлы

Каждому дашборду соответствует отдельная папка:

```text
dashboards/
└── linear-function/
    ├── index.html
    ├── README.md
    └── assets/
```

`README.md` описывает учебную цель, источники данных и способ запуска. Создавай `assets/` только при необходимости. Ресурсы подключаются относительно HTML, например `assets/chart.js`; пути вида `/assets/chart.js` через Lavish не работают.

## Просмотр и обратная связь

Открыть существующий HTML:

```bash
npm run lavish -- dashboards/linear-function/index.html
```

Вместо `linear-function` подставь название своего дашборда. CLI запускает локальный сервер и открывает окно просмотра; если окно не открылось автоматически, используй URL из вывода команды.

1. Изучи материал и проверь ползунки, кнопки и другие взаимодействия.
2. Для замечания включи режим аннотирования, нажми на элемент или выдели текст и запиши, что нужно изменить.
3. Отправь подготовленные замечания кнопкой **Send to Agent**. До отправки они остаются в очереди.
4. Агент получает замечания через команду `poll`, исправляет исходные файлы и отправляет ответ. При сохранении HTML просмотр обновляется автоматически.
5. Для завершения обсуждения используй **Send & End**: эта кнопка отправляет последние замечания и завершает сеанс.

Сообщение, отправленное внутри Lavish, агент получает через `poll`. Важно, чтобы результат этой команды прочитал активный агент. Если ход Codex уже завершён, оставшийся процесс `poll` может забрать сообщение, но не возобновить работу модели. Для продолжения напиши в основном чате Codex: «Прочитай замечания Lavish к dashboards/ai-basics/index.html, внеси правки и ответь в Conversation».

## Как запускается агент и что значит Working

Lavish — редактор просмотра и канал обратной связи. Команда открытия HTML запускает локальный сервер и страницу; она не запускает Codex, не выбирает модель и не делает запросы к модели для выполнения ваших поручений. Панель Conversation относится к текущему HTML-сеансу и не является самостоятельным чатом с ИИ.

Для обработки замечаний нужен запущенный агент с доступом к проекту и командной строке. Навык Lavish уже установлен в `.agents/skills/lavish/`. В Codex CLI можно начать работу из корня проекта командой `codex`; в приложении Codex нужно открыть этот локальный проект. Дальше дай агенту поручение прочитать и обработать замечания Lavish.

Последовательность работы:

1. Пользователь открывает дашборд и отправляет замечания через **Send to Agent**.
2. Активный агент выполняет `npm run lavish -- poll dashboards/ai-basics/index.html` и получает сообщения с привязкой к элементам страницы.
3. Агент читает ответ команды, исправляет файлы и выполняет необходимые проверки.
4. Агент отправляет ответ командой `reply`. Сервер принимает его, статус Working исчезает.

`poll` — получение сообщений. Если запустить его вручную в отдельном терминале, он выведет сообщения, но не запустит ИИ и не выполнит правки.

Главный индикатор **Working** означает, что сообщения уже забраны через `poll` и сервер ещё не получил ответ агента. Он не измеряет активность модели и может сохраняться после прекращения работы агента. Значки доставки у отдельных замечаний показывают отдельные события: получение, изменение HTML и ответ.

В Codex нельзя обещать автоматическое продолжение только на основании того, что процесс `poll` ещё жив. Ожидание должно оставаться в активном ходе агента, либо нужен отдельно настроенный и проверенный механизм пробуждения. Навык, хук запуска сеанса и сама команда открытия HTML такой гарантии не дают.

## Команды для агента

Перед созданием HTML прочитай навык и актуальные рекомендации установленного CLI:

```bash
npm run lavish -- --help
npm run lavish -- design
npm run lavish -- playbook
```

Последняя команда перечисляет доступные руководства. Затем открой подходящие, например для объяснения и схем:

```bash
npm run lavish -- playbook explanation
npm run lavish -- playbook diagram
```

Ожидание замечаний к открытому материалу:

```bash
npm run lavish -- poll dashboards/linear-function/index.html
```

`poll` долго ожидает без вывода — это нормальное поведение. Для Codex ожидание должно оставаться привязанным к активному ходу; не запускай его через `nohup` или отдельный фоновый процесс без механизма уведомления агента.

После выполнения правок отправь краткий ответ в окно Lavish:

```bash
npm run lavish -- reply dashboards/linear-function/index.html --agent-reply "Добавлены подписи осей и кнопка сброса."
```

Если нужно отправить ответ и сразу продолжить ожидание:

```bash
npm run lavish -- poll dashboards/linear-function/index.html --agent-reply "Правки готовы. Можно проверить."
```

Если пользователь завершил сеанс в браузере, повторно открывай его только по запросу на дальнейший просмотр, используя `--reopen`.

## Публикация материалов

Все дашборды проекта публикуются как работающие интерактивные страницы в [GitHub Pages](https://plat01.github.io/ai-tutoring/). Порядок добавления и обновления материалов — в [github-pages.md](github-pages.md). Отдельные HTML-экспорты для передачи не создаются без явного запроса пользователя.

GitHub Pages показывает сам учебный материал. Панель Conversation и аннотации Lavish доступны в локальном редакторе, запущенном через CLI.

Публикация через `share` — отдельное действие: она отправляет материал стороннему сервису ht-ml.app, а страницы по умолчанию публичны. Перед публикацией прочитай `npm run lavish -- share --help` и согласуй её с пользователем. Для обычного локального просмотра публикация не нужна.

## Завершение и диагностика

Завершить конкретный сеанс командой агента:

```bash
npm run lavish -- end dashboards/linear-function/index.html
```

Остановить сервер Lavish, когда остальные открытые сеансы больше не нужны:

```bash
npm run lavish -- stop
```

- CLI не найден: выполни `npm ci` в корне проекта.
- HTML не найден: проверь путь и наличие файла; команда открытия сама не создаёт дашборд.
- Картинка или скрипт не загружается: проверь относительные пути и расположение ресурсов внутри папки дашборда.
- Агент не получает замечания: проверь, что нажата **Send to Agent** и агент получает результат `poll` в активном ходе. Самостоятельный процесс ожидания не заменяет агента.
- Working висит без результата: попроси Codex прочитать замечания и состояние сеанса; уже доставленные сообщения могут оставаться в истории Conversation, даже если новая очередь пуста. Не отправляй фиктивное «готово» для сброса индикатора: ответ должен соответствовать реально выполненной работе.
- Экспорт не работает без сети: проверь внешние CDN-ссылки и замени необходимые ресурсы локальными.

Инструкция опирается на справку установленного CLI. При обновлении версии сверяй команды с `npm run lavish -- --help`. Исходный проект и документация автора: [kunchenguid/lavish-axi](https://github.com/kunchenguid/lavish-axi).
