# Контекст проекта

Этот проект — рабочая площадка для экспериментов с MCP-серверами и навыками (skills), а также для создания дашбордов и наглядных учебных материалов для учеников.

## Общение и подход

- Общайся с пользователем на русском языке.
- Делай объяснения понятными и конкретными. Для учебных материалов учитывай возраст, уровень подготовки и тему занятия; если они неизвестны и влияют на результат, уточни их.
- Предпочитай небольшие, самостоятельные эксперименты. Не вводи общий стек или сложную инфраструктуру без необходимости.
- Перед изменениями осмотри существующие файлы и инструкции. Сохраняй чужие изменения.

## MCP-серверы и навыки

- Используй доступные инструменты и подходящие навыки для поставленной задачи; читай инструкции выбранного навыка перед применением.
- Для каждого эксперимента фиксируй его цель, зависимости, способ запуска и результат в локальном README.
- Отличай проверенные возможности от предположений. При ошибках записывай условия воспроизведения и ограничения.
- Не сохраняй токены, пароли и другие секреты в исходниках, примерах, логах и документации. При необходимости используй переменные окружения и примеры конфигурации без секретов.

## Дашборды и учебные материалы

- Все новые дашборды создавай с помощью Lavish (`lavish-axi`): сохраняй HTML и локальные ресурсы в `dashboards/<название>/`, открывай HTML через Lavish для просмотра и обратной связи.
- Все дашборды должны быть доступны как работающие интерактивные страницы через GitHub Pages. Храни исходники в репозитории GitHub, поддерживай общий каталог дашбордов и проверяй опубликованный адрес после изменений.
- Не создавай отдельные HTML-экспорты для передачи, если пользователь явно не попросил. Основной результат для пользователя — ссылка на дашборд в GitHub Pages; Lavish используй для локального просмотра и обратной связи.
- Перед работой с дашбордом читай `.agents/skills/lavish/SKILL.md`, затем получай актуальные инструкции командами `npm run lavish -- --help`, `npm run lavish -- design` и подходящим `playbook`.
- Используй установленную в проекте версию CLI через `npm run lavish -- <команда или путь к HTML>`. Зависимости восстанавливаются командой `npm ci`; инструкции запуска описаны в корневом `README.md`.
- Получай замечания Lavish через `poll` в активном ходе агента. Не оставляй `poll` после завершения хода как замену автоматическому пробуждению Codex. Если замечания уже доставлены, но обработка не началась, прочитай историю сеанса, выполни правки и отправь подтверждённый `reply`.
- Начинай с учебной цели: что ученик должен понять или научиться делать.
- Выбирай формат под задачу: интерактивный дашборд, схема, симуляция, график, презентация или документ.
- Делай подписи, единицы измерения и инструкции понятными; не полагайся только на цвет для передачи смысла.
- Указывай источники данных и существенные допущения. Явно помечай демонстрационные и синтетические данные.
- Проверяй расчёты, читаемость и итоговый вид материалов. Для интерактивных материалов проверяй основные сценарии использования.
- Сохраняй исходники вместе с инструкциями по запуску или воспроизведению результата и ссылкой на опубликованную страницу GitHub Pages.
- Не включай персональные данные учеников в публикуемые материалы и примеры.

## Организация файлов

Проект пока не имеет установленного стека. Создавай каталоги по мере необходимости:

- `experiments/` — эксперименты с MCP-серверами и навыками;
- `dashboards/` — дашборды;
- `materials/` — учебные материалы;
- `data/` — данные и описание их происхождения.
- `docs/` — документация по инструментам и работе с проектом; инструкция по Lavish — `docs/lavish.md`.

Используй понятные названия папок для отдельных задач. Не создавай пустые заготовки заранее.

## Проверка и завершение

- Выполняй проверки, подходящие к изменению: запуск примера, проверку вычислений, просмотр рендера или проверку взаимодействий.
- В итоговом сообщении кратко указывай, что создано или изменено, где найти результат и как его открыть или запустить.
- Если проверку выполнить невозможно, явно сообщай об этом.
